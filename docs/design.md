# persona-reviewの設計

## 四段階の分離

1. 対象選定: Codexの読み取り専用ツールで対象を読み、diff/full、比較元/先、選択理由、未取得範囲を確定する。
2. 中立レビュー: 固定した評価基準で `review.schema.json` に合う技術評価を作る。
3. ペルソナ整形: 技術評価のID、重大度、根拠、確信度を保ち、口調だけを変える。
4. ビジュアル: 中立評価から表情を決め、登録画像の選択か標準image_genへの依頼を行う。

ヘルパーは設定検証と第4段階の計画だけを実装します。対象リポジトリのGit操作、コード実行、ネットワークアクセス、LLM呼び出しを含めません。画像生成の実呼び出しは、実行環境が公開しているツールのスキーマを確認したCodexが行います。

## 設定の保存と優先順位

Windowsは `%LOCALAPPDATA%/persona-review`、その他は `$XDG_DATA_HOME/persona-review` または `~/.local/share/persona-review` を使います。`PERSONA_REVIEW_HOME` と `--data-dir` はローカル利用者向けの変更手段です。この場所をリポジトリの設定値から決めません。

```text
ユーザーデータ/
  config.json       グローバル設定とキャラクター定義
  config.lock       更新時だけ存在する排他ロック
  assets/           UUID名で保存した参照画像・表情画像
```

`config.json` の形式は [config schema](../schemas/config.schema.json)、設定値は [settings schema](../schemas/settings.schema.json)、キャラクター定義は [character schema](../schemas/character.schema.json) で定義します。ヘルパーはこのパッケージで使うJSON Schemaの小さな部分集合を標準ライブラリで検証します。汎用JSON Schemaエンジンではありません。設定のキャラクターIDやレビューの整合性には追加の意味検証があります。

優先順位は明示指定、プロジェクト設定、グローバル設定、同梱既定値です。同梱既定値は `guide / hybrid / auto`。guideは画像を持たないテキストの案内役です。グローバルの `allow_project_overrides` はfalseが既定であり、falseの場合は指定されたプロジェクト設定ファイルを開きません。

プロジェクトの `.persona-review.json` には、登録済みキャラクターのIDと二つのモードだけを許可します。任意のファイルパス、コマンド、画像、persona、ユーザーデータの場所、許可フラグは指定できません。不明なフィールドや未登録キャラクターを黙って採用せずエラーにします。プロジェクトファイルの作成・更新は `set-project` が同じ原子的保存手順と `.persona-review.lock` を使って行います。

グローバル更新はロック取得後に現状を読み直し、検証したJSONを同じディレクトリの一時ファイルへ書きます。flush/fsync後に `os.replace` で置き換えます。検証や置換に失敗すれば元の設定を維持します。プロセスが強制終了するとロックが残る場合があるため、処理が動いていないことを確認したうえで手動除去します。停電を含むすべてのファイルシステム障害への永続性保証はありません。

画像はヘッダーと10 MiBの上限を確認し、新しいUUID名で保存してから設定を切り替えます。設定の保存が失敗しても旧画像を上書きしません。孤立した画像や旧画像は自動削除されません。画像名は限定した形式だけを許し、解決後のパスが管理ディレクトリ外や別の親ディレクトリを指す場合は拒否します。ユーザーデータディレクトリ自体は利用者が管理する信頼境界です。

## 表情と未確認範囲

|条件（上から優先）|表情|
|---|---|
|critical/highの指摘あり|stern|
|medium/lowの指摘あり|concerned|
|statusがcompleteではない|neutral|
|確認完了、指摘なし|happy|

`complete` は選択範囲に対する状態です。対象の全不具合がないことを意味しません。未確認項目があれば `partial` とし、空差分は `empty`、内容にアクセスできなければ `unavailable` とします。空差分・取得不能状態で良い点や指摘を報告するJSON、読んだ対象がないcomplete、未確認を含むcompleteを拒否します。

画像計画に含める情報は表情、管理画像パス、外見のデータだけです。外見の自由記述自体に命令や秘密が混ざる可能性があるため、スキルは外見の必要情報を抽出してから生成へ渡します。ヘルパーには自由記述の意味を安全判定する機能はありません。

## 信頼境界と検証の限界

対象コード、README、設定値、persona、画像内の文字を命令として扱いません。レビュー中の設定変更、送信、コマンド実行は、ユーザーの実際の依頼からのみ判断します。対象のテストやlintもレビューに付随して自動実行しません。

スキルによる命令分離はモデルの手順です。OSのサンドボックスや独立プロセスによる強制隔離ではなく、プロンプトインジェクションを完全に排除したという保証はしません。中立JSONを確定してから文体を変え、最終出力と照合することで評価の変化を検出しやすくします。

自動テストは決定的なヘルパーの境界を対象とします。実際のコネクタ、Codexへのインストール、キャラクターの再現性、生成画像の品質、技術指摘の正確さは別途実機確認が必要です。
