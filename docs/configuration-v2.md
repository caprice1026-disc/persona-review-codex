# 設定v2と旧設定の移行

キャラクターは `name / appearance / images / persona_id`、人格は `name / style` を持ちます。キャラクターの `persona_id` は既定人格です。設定側の `persona_id` は、その既定値を上書きして選ぶ人格です。`default` を指定すると選択キャラクターの既定人格を使います。guideの人格と画像なしキャラクターは同梱されています。

```json
{
  "version": 2,
  "allow_project_overrides": false,
  "settings": {
    "character_id": "mina",
    "persona_id": "default",
    "image_mode": "cached_only",
    "scope": "file",
    "focus": ["security", "performance"]
  },
  "characters": {
    "mina": {
      "name": "ミナ",
      "appearance": "紺色の上着",
      "persona_id": "calm",
      "images": {}
    }
  },
  "personas": {
    "calm": {"name": "落ち着いて率直", "style": "根拠を短く率直に説明する。"}
  }
}
```

同じ人格を別のキャラクターの既定値に指定できます。`register-persona` でその人格を更新すると参照先すべてに反映されます。1つのキャラクターだけに異なる文体を使いたい場合は別IDを登録します。IDや話し方を変えても画像キャッシュは変わりません。外見・名前・キャラクターID・参照画像を変えた場合は別の画像として扱います。

旧形式の `register` は対象キャラクターの編集として扱います。人格の内容を変更する場合は空いている専用IDを割り当て、既存人格や他キャラクターの参照を変更しません。現在の人格と同じ内容なら既存の参照を保持します。自動生成候補のIDが別用途で使われている場合も上書きせず、別IDを使います。旧人格は削除せず、明示的に選択されたグローバル・プロジェクトの人格IDも維持します。

## 範囲と重点

`scope` は `auto / diff / full / file`。autoの実際の対象選択はreviewスキルが依頼に従って行い、ヘルパーが対象コードを読むことはありません。中立JSONには解決後の diff/full/file と対象、選択理由を記録します。重点は `focus` の配列で指定し、correctness/security/performance/architecture/maintainability/testingを使えます。空配列は重点を限定しない指定です。ファイルパスはここに保存せずレビューの依頼で渡します。

明示指定 > 許可されたプロジェクト設定 > グローバル > 同梱既定値の順に、項目ごとに解決します。scopeだけの変更でfocusは消えません。focus配列は上位層で置き換え、空配列で下位の重点を解除できます。persona_idも同じ順位です。defaultの解決後、返却値は実際の人格IDになり、sourceはcharacter_defaultになります。

旧 `character` は `character_id`、`review_mode` は `scope` の別名です。各階層で別名を正規化してから統合するため、上位の旧別名も下位の新名より優先します。同じ階層の新旧値が矛盾する場合は拒否します。`set` / `set-project` は指定した同義項目を置き換え、他の設定を保持します。解決結果には旧利用側向けのcharacter/review_modeも残します。

## 読み取り・移行・復旧

v1の `config.json` と旧キャラクター定義は引き続き読めます。`show` は保存されている版を表示します。`resolve` はメモリ内で独立した人格を作り、設定ファイルを書き換えません。旧キャラクターごとのpersona文字列にはキャラクターID由来の安定した専用IDを割り当てます。日本語の値、参照画像、旧表情スロットを保持します。

`migrate` または次の設定保存でv2を保存します。排他ロック内で旧画像の識別情報を履歴へ取り込み、元の設定を `config.v1-backup-<元バイト列のSHA256>.json` へそのままバックアップしてから、検証済みv2を一時ファイルから置換します。バックアップは同じユーザーデータ内に置きます。設定と同様に私的な内容なのでコミットしません。画像計画だけでは設定をv2へ書き換えませんが、旧画像履歴の初回作成は行います。

検証・バックアップ・設定置換に失敗した場合は成功を報告せず、旧設定を維持します。書き込み失敗後は空き容量・権限などの原因を解消して同じ操作を再実行できます。バックアップの内容不一致は上書きせずエラーにします。処理中に残る可能性のある旧画像や孤立画像、履歴を自動削除しません。停電を含むあらゆる障害への耐久性を保証するものではありません。

旧版へ戻す必要がある場合は実行中処理を止め、現在のconfigとassets/image-recordsを別途保全し、正しいバックアップを確認してconfig.jsonへ復元します。v2移行後に旧バイナリから設定を書き戻す運用は対象外です。クラッシュ後のconfig.lockは実行中処理がないことを確認して扱います。

## 画像生成を禁止するモード

cached_onlyは保存画像の使用だけを許可します。参照画像が存在しても、未登録・破損・ハッシュ不一致などで使える表情がなければunavailableとなり、生成計画を返しません。初期セットやforce指定でも同じです。本文と中立JSONは保持し、表示できない理由を添えます。

旧Aはalways、旧Bはpre_generateへ解決します。Bをcached_onlyへ変更する移行ではありません。初期セットはhappy/neutral/concerned/sternの4表情に限定します。
